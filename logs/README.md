# logs/ — AI interaction log

Everything in this folder is generated by `.claude/hooks/ai-log.js`. The hooks are wired in `.claude/settings.json`. The record schema is described at the end of this file, and every record has the same keys in the same order.

| File | What it is | Written by |
|---|---|---|
| `ai-interactions.jsonl` | One JSON record per interaction: prompt, tool call, sub-agent, skill, MCP call, verification, response, human decision, guard block, stage change | Hooks (live). `rebuild` regenerates it from the Claude Code transcripts, which are the ground truth |
| `AI_INTERACTION_LOG.md` | Readable summary: header (tool, models, sessions, totals), one section per stage (table, full prompts, final responses), human oversight, verification appendix | Rendered from the JSONL on every `Stop`, `human`, `rebuild` and `render` |
| `HUMAN_OVERSIGHT.md` | Human decisions: recorded verdicts, plus rejected tool calls and interrupts found automatically | Rendered from the JSONL and `human-decisions.jsonl` |
| `human-decisions.jsonl` | Source of truth for decisions recorded with the `human` command. `rebuild` merges it back | `human` command |
| `stages.json` / `.stage` | Stage history and the current stage name. Each record is tagged with the current stage | `stage` command |
| `.state.json` | Hook scratch state: the current prompt id and the tools used in this turn | Hooks |

## Commands (run from the repo root)

```bash
node .claude/hooks/ai-log.js stage step1-single-approver                    # start a new stage
node .claude/hooks/ai-log.js human "Rejected the AI's rounding change" --status rejected [--related <record id>]
node .claude/hooks/ai-log.js rebuild ~/.claude/projects/<project-folder>    # regenerate from transcripts (files or folders)
node .claude/hooks/ai-log.js render                                         # re-render the Markdown from the JSONL
node .claude/hooks/ai-log.js --selftest                                     # self-check in a temp folder
```

Set `AI_LOG_DIR=<folder>` to write to a different folder, for example for a dry run.

## Guarantees

- The logger never blocks a session. Every error is swallowed and the hook always exits with code 0.
- Secrets are redacted before anything is written: GitHub tokens, `Bearer` tokens, AWS keys, `sk-` keys and passwords. The documented demo password is kept.
- Model thinking blocks are never logged.
- Live hooks write `model: "unknown"` when the transcript tail has no model yet. `rebuild` fills in the exact model, the Claude Code version, the sub-agent attribution, the stages and the commit references, using a read-only `git log`.

## Machine-specific redaction (not committed)

Company-internal host names, client names and similar private strings are redacted through an optional, git-ignored list `.claude/hooks/redact.local.json` (JSON array of `{ "pattern": "<regex>", "label": "<name>" }`, override path with `AI_LOG_REDACT_FILE`). The committed code only contains generic rules (tokens, keys, passwords, e-mail addresses), so it never reveals what the local list hides.

## Record schema

Every line of `ai-interactions.jsonl` is one JSON object with these keys, always all present and always in this order (empty values are `null` or `[]`):

`id`, `timestamp`, `stage`, `agent`, `agent_name`, `agent_type` (built-in / custom / sub-agent / human), `ai_tool`, `model`, `mode` (plan / agent), `event` (session_start, user_prompt, human_checkpoint, tool_use, verification, subagent, skill, assistant_response, human_decision, stage_change, guard_block, slash_command), `related_ids`, `parent_task`, `context`, `request`, `skills_used` [{name, type, purpose, invocation}], `subagents_used` [{name, type, task, status}], `mcp_tools_used` [{server, tool, purpose}], `tools_used`, `suggestion`, `human_decision`, `action_verification`, `limitation`, `status` (applied / rejected / partial / info), `artifacts`, `commit`, `session_id`.

The schema follows the reviewer's sample format (tool and model, agent type and mode, prompts, skills, sub-agents, MCP tools, actions and outputs, human decisions, execution evidence, outcome) and adds `event`, `commit` and `session_id` for traceability.
